sec_bat_get_property:
  Switch jump table: .rodata+0x110, target=0x123d8 + byte[property]*4.
  Property 20 -> 0x12428, selector value initialized to 0 at 0x1242c.
  Property 21 -> 0x12488, selector value initialized to 2 at 0x1248c/0x12490.
  Both branches call the fuel-gauge get_property with property 1051 (0x41b),
  set at 0x124bc; the result is returned without a watts conversion.

max77775_fg_get_property:
  Extended switch .rodata+0x64, target=0x4e2c + uint16[property-0x40e]*4.
  Property 1051 -> 0x52e8.
  Selector 0 -> 0x5494 -> max77775_fg_read_isys(..., 1).
  Selector 2 -> 0x5304 -> max77775_fg_read_isys_avg(..., 1).
  In those functions, mode 1 is mA; mode 0 is uA.
  read_isys selects .rodata.str1.1+0x37f ("mA") for nonzero mode and
  .rodata.str1.1+0x8a1 ("uA") for zero mode. The scale differs by 1000.

Kernel logs independently label these quantities:
  ISYS(...mA), ISYSAVG(...mA), VSYS(...mV), IIN(...mA), VBYP(...mV), QH(...uah)
Saved in fuelgauge-kernel-log.txt and fuelgauge-power-log.txt.

Conclusion: battery/power_now is ISYS mA and power_avg is averaged ISYS mA
on this firmware. This confirms software meaning/units, not absolute accuracy,
physical coverage of the sensing circuit, or total-device power calibration.
