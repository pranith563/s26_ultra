CPU and HTP each executed both inputs successfully as ordinary ADB shell

  runs\qnn-htp\20261114T130003Z\analysis.json
  runs\qnn-htp\20261114T130003Z\qnn-profile.txt
  runs\qnn-htp\20261114T130003Z\htp.perfetto-trace

Clock alignment matters: qprof uses ARM CNTVCT ticks times 52.08333 ns;
QNN uses MONOTONIC microseconds and Perfetto uses BOOTTIME nanoseconds.
On this boot, qprof's timestamp base is approximately 6.273426 seconds ahead
of BOOTTIME. clock_probe.cpp samples the clocks before/after each workload.
The final run's aligned-qprof folder adds BootTimestamp_ns and QnnPhase
columns using those paired measurements. Raw CSVs are preserved in qprof.
NPU utilization increases during the marked workload and decreases afterward.
This confirms useful correlation, not calibration of every hardware counter.
The offset must be measured again after reboot; do not reuse a fixed offset.

Repeat a bounded capture from this workspace:
  python -u .\run_htp_profile.py
The runner uses the already staged model/libraries/clock probe, starts the
isolated profiler, captures ten seconds around the workload, saves commands
and device metadata in a new UTC-named directory, then stops its server and
removes its ADB forward. It preserves raw captures and clock probes; the
aligned CSVs and analysis.json above were generated in a separate analysis
step. Keep the phone connected for the entire run.

This is a functional profiling test with observer overhead and default
power policy, not a throughput comparison. Source operations may be fused,
so detailed profiling does not time each original layer independently.
GPU counter validation and external GPU/HTP DMA-BUF import remain open.
No claim of zero-copy execution is established by these tests.
